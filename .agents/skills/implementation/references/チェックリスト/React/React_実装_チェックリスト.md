# 実装 チェックリスト（React）

> **注記**：本チェックリストが対象とするReactは、公開版v1時点では動作未検証の技術スタックです。FastAPIを正式サポート対象とし、Reactでの動作確認が取れ次第、正式サポートへ格上げします。

## Hooksの使用

- [ ] 「親のprops変化に応じて子のローカルstateをリセットする」処理を、Effect内で条件なしにsetStateを呼ぶ書き方（`react-hooks/set-state-in-effect`が指摘するアンチパターン）で実装していないか
- [ ] Lintルールを新規導入・強化する際、既存コードへの影響範囲を事前に横断検索してから一括対応か個別対応かを判断したか
- [ ] 抑制コメントでLint違反を許容する場合、判断理由をコメントに残し、後続の修正で同じルール違反を誤って作り込んでいないか確認したか

## 非同期状態管理

- [ ] 非同期でサーバー状態を復元する機能では、成功時の状態遷移だけでなく、失敗時に再試行・別手段で操作継続できる状態遷移も同時に設計・実装したか
- [ ] 「未着手」「読み込み中」「復元成功」「復元失敗」等の状態を列挙してから実装に着手し、いずれかの状態を欠落させたまま完了としていないか

## PoC承認内容の反映確認

- [ ] PoC（試作画面）で承認された改修項目を実装完了時にチェックリスト化し、項目単位で実装済みか突き合わせたか
- [ ] PoCの視覚的な確認内容（画面イメージ・挙動）と設計書のテキスト記述との間に解像度の差が生まれやすいことを前提に、設計書の記載だけでなくPoC承認時の画面イメージ自体も突き合わせたか
- [ ] 複数の改修項目を一括でPoC承認した場合、実装完了報告の際に「全項目が反映されているか」を機能単位ではなく項目単位で確認したか

## ビルド・Lintの実行確認

- [ ] 実装工程の完了判定に、`npm run build`・`npm run lint`等の品質確認コマンドを実際に実行しエラーなく完了することの確認を含めたか
- [ ] 品質確認コマンドを新規定義する際、それが実際に実行可能な状態（依存関係・設定ファイルが揃っている）であることをその場で検証したか
