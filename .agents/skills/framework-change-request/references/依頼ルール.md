# 依頼ルール

- このサブモジュールを利用するプロジェクト（依頼元）は、本リポジトリを直接編集しないこと。
- 依頼元プロジェクトが行うのは、依頼内容をissue本文へ直接記載し、開発元プロジェクトへ連絡することのみである。
- issueの連絡先は`hojou`自身のリポジトリ`ku-kaname/hojou`とする。
- 検討中はissue自体（Open/Close・本文）で進行状況を管理する。非採用が決まった時点、または採用した依頼の対応が完了した時点で、[変更履歴・非採用一覧.md](../../../../変更依頼/変更履歴・非採用一覧.md)へ1行追記することが、唯一かつ恒久的な記録である（採用が決まっただけの段階では追記せず、issueをOpenのまま管理する）。

## 運用フロー

1. 依頼元プロジェクトが、依頼内容をissue本文へ直接記載し、`ku-kaname/hojou`へissueで連絡する。
   - 例）
      ```bash
      gh issue create --repo ku-kaname/hojou --title "【変更依頼】<依頼内容>" --body "<依頼目的・依頼内容>"
      ```
   - フォーマットは下記「issue本文のフォーマット」参照。
2. 開発元プロジェクトが内容を精査し、状態を判断する。検討中はissue自体（Open/Close・本文）で進行状況を管理し、`変更依頼/`へのファイル格納は行わない
   - 対応する場合／精査中：issueはOpenのまま
   - 対応しない場合：判定日・依頼内容・非採用理由・issueへのリンクを[変更履歴・非採用一覧.md](../../../../変更依頼/変更履歴・非採用一覧.md)の「非採用一覧」へ記録し、issueをcloseする
3. 採用した依頼の対応が完了したら、対応日・変更内容・issueへのリンクを[変更履歴・非採用一覧.md](../../../../変更依頼/変更履歴・非採用一覧.md)の「変更履歴」へ記録し、issueをcloseする


## issue本文のフォーマット

```markdown
# <依頼内容>

# 依頼目的

- この依頼対応により達成したいことを記載。

# 依頼内容

- 依頼の経緯と具体的な内容を簡潔に記載。

```
