# Issueルール

## タイトル形式

```
【工程】作業内容【操作】
```

### 工程の種類

| 工程 | 用途 |
|---|---|
| `【要件定義】` | 要件定義書の作成・修正 |
| `【設計】` | 設計書・レビュー指摘表の作成・修正 |
| `【実装】` | コード・レビュー指摘表の作成・修正  |
| `【単体テスト】` | テスト仕様書・テストコード・レビュー指摘表の作成・修正  |
| `【結合テスト】` | テスト仕様書・レビュー指摘表の作成・修正  |
| `【プロジェクト完了】` | README・機能別引継ぎ資料の一括作成 |
| `【その他】` | 環境設定・開発方針など上記に当てはまらない作業 |

プロジェクト改修では、新規タグを設けず、バックログで修正する成果物の種類に応じて上記の既存タグを使い分ける（例：要件定義書を修正するバックログは`【要件定義】`、設計書を修正するバックログは`【設計】`）。運用ルール文書自体の改訂など、特定の成果物種類に対応しないバックログは`【その他】`を使う。

### 操作の種類

| 操作 | 用途 |
|---|---|
| `【作成】` | 新規ファイル・機能の作成 |
| `【追加】` | 既存ファイル・機能への追加 |
| `【修正】` | 誤り・不備の修正（レビュー指摘対応を含む） |
| `【レビュー】` | 設計書・コードへのレビュー指摘（レビュー指摘表の作成） |
| `【確認】` | レビュー指摘対応の再鑑・確認 |

### タイトル例

```
【要件定義】要件定義書の格納【作成】
【設計】レビュー指摘表の格納【レビュー】
【設計】レビュー指摘対応（CRUD/ユーザー操作）【修正】
【実装】全ユーザー情報取得【作成】
【その他】設計書記載方針追加【追加】
```

## 概要テンプレート

```markdown
## 作業スコープ
- 対象ファイル・機能を記載

## 完了条件
- [ ] 完了したらクローズする条件を記載

## 関連（任意）
- 指摘No.番号 / 関連Issue番号など
```

### 記載例（レビュー指摘対応）

```markdown
## 作業スコープ
- 設計書/CRUD/ユーザー操作 配下の指摘対応

## 完了条件
- [ ] 指摘No.1 ユーザー作成 対応完了
- [ ] 指摘No.1 ユーザー情報削除 対応完了
- [ ] 指摘No.2 ユーザー情報削除 対応完了
- [ ] 指摘No.3 ユーザー情報削除 対応完了
- [ ] 指摘No.1 ユーザー情報取得 対応完了
- [ ] 指摘No.1 ユーザー情報更新 対応完了
- [ ] 指摘No.2 ユーザー情報更新 対応完了
- [ ] 指摘No.1 全ユーザー情報取得 対応完了
- [ ] 指摘No.2 全ユーザー情報取得 対応完了

## 関連
- なし
```

### 記載例（設計書作成）

```markdown
## 作業スコープ
- 設計書/CRUD/ユーザー操作 配下の設計書を格納

## 完了条件
- [ ] ユーザー作成 設計書作成完了
- [ ] ユーザー情報取得 設計書作成完了
- [ ] ユーザー情報更新 設計書作成完了
- [ ] ユーザー情報削除 設計書作成完了
- [ ] 全ユーザー情報取得 設計書作成完了

## 関連
- なし
```

## PRのタイトルと概要

IssueとPRは1:1対応のため、PRタイトルはIssueタイトルをそのまま使用する。

### タイトル

```
【設計】レビュー指摘対応（CRUD/ユーザー操作）【修正】
```

### 概要

```markdown
Closes #○○
```

`Closes #○○` を記載することでマージ時にIssueが自動クローズされる。

PRマージ・Issueクローズを確認したら、対応したブランチをローカル・リモート双方から削除する（マージ済みブランチへの追加コミットは行わない。再度対応が必要になった場合は新たなIssue・ブランチを作成する）。

## PRに含める変更

PRには、対応するIssue（バックログ）の「作業スコープ」「完了条件」に属する変更のみを含める。PR（＝1バックログ）の規模は、[作業管理ルール](../作業管理ルール/作業管理ルール.md)「1PRの規模の目安」に収める。

### 含めてよい付随変更

以下は、作業スコープに明記されていなくても、同じPRに含めてよい。

- 当該バックログの作業管理・引継ぎ資料の更新（状態の`完了`への更新を含む。[作業管理ルール](../作業管理ルール/作業管理ルール.md)「タスクの完了・追加」参照）
- 本PRの変更に伴って必要になった追従修正（ファイル名の変更に伴う参照の修正等）
- 範囲外の依頼を受けた際の`【一覧取込待】_<バックログ名>.md`の作成（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「対応中バックログの範囲を超える依頼への対応」参照）
- バックログの分割に伴う`バックログ一覧.md`の更新（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「バックログの分割単位」「作業中のバックログ分割」参照）
- 当該バックログのレビュー工程で、影響がある他の機能群の成果物へ指摘した箇所の修正（[レビュー工程ルール](../開発ルール/レビュー工程ルール.md)「手順」1参照）
- 作業中に見つけた軽微な誤りの修正のうち、以下をすべて満たすもの
    - 本PRで既に変更しているファイル内の箇所である
    - 誤字・旧名称・リンク切れ・古くなった説明等の表記の修正であり、内容・ルールの意味を変えない
    - 修正内容をPRの概要に記載する

### 含めない変更

- 他のバックログに属する変更
- 上記の付随変更に当たらない範囲外の修正（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「対応中バックログの範囲を超える依頼への対応」に従う）
- 完了バックログの`bk/`への格納（本体PRのマージ確認後、専用のIssue・PRで行う。[作業管理ルール](../作業管理ルール/作業管理ルール.md)「タスクの完了・追加」参照）

### 機械的な一括変更

工程・機能群をまたぐ多数のファイルへ同じ種類の変更を機械的に行うもの（プロジェクト完了時の成果物のv1.0.0への更新に伴うファイル名の変更、テンプレート改訂に伴う一括修正等）は、内容の変更と同じPRに含めず、単独のバックログ・PRで行う。この変更に伴う追従修正（ファイル名の変更に伴う参照の修正等）は、同じPRに含めてよい。

## コミットとの紐付け

IssueはPRと1対1で対応させ、PRには関連するコミットをまとめる。  
詳細は [コミットルール](コミットルール.md) を参照。

```
Issue（完了条件のチェックボックス）
  └── branch: feature/XX
        ├── commit: [fix] ユーザー作成 指摘No.1 ...
        ├── commit: [fix] ユーザー情報削除 指摘No.1 ...
        └── commit: [fix] ユーザー情報削除 指摘No.2 ...
  └── PR → merge → Issueクローズ
```
