# 設計 Codex指摘・再鑑時チェックリスト

> **注記**：本チェックリストが前提とするCodex運用は、公開版v1時点では動作未検証の実験的機能です。Claude運用を正式サポート対象とし、Codexでの動作確認が取れ次第、正式サポートへ格上げします。

Codex（GPT-5）によるレビュー指摘・再鑑で実際に発生した指摘ミスを基にした、設計工程向けのセルフチェック項目。技術スタックに依存しない、指摘・再鑑プロセス上の観点を扱う。人手（Codexによる自己再鑑を含む）でのレビュー時に使用する。

## MVP対象・対応時期の判定

- [ ] 認証系のセキュリティ強化（メールアドレス単位のクールダウン、信頼済みプロキシを限定した実クライアントIP取得等）を、本番インフラ構成確定前の現段階で対応必須と誤認していないか。バックログ対応と判断済みであれば、その判断を指摘の前提として踏襲したか
- [ ] 排他制御の対策拡大（検証範囲の拡大、定期的な状態更新等）を、低頻度リスクへの追加対策と現段階の必須対策のどちらとしてユーザーが判断済みか確認したか
- [ ] 技術的なリスクが存在することと、現在のMVP受入条件に含まれることを分けて判定したか
- [ ] 指摘候補を「現在のMVP対象」「MVP対象外・バックログ」「対応要否未確定」のいずれかに分類し、判断根拠書・バックログ・引継ぎ資料と照合したか

## 対象成果物の事実確認

- [ ] 指摘対象の設計書が現行版であることを確認し、旧版・別階層・別機能の同名設計書と取り違えていないか
- [ ] 指摘する値・列挙・記載内容が、対象の設計書ファイルに実際に存在することを最後まで読んで確認したか
- [ ] 関連する要件定義書・上位設計書を参照する場合、それが現行版（改訂反映済み）であることを確認したか

## 再鑑時の確認

- [ ] 一度MVP対象外・バックログと確定した事項を、再鑑で「未解消」「記載不足」「対応範囲の表現精緻化」等の別表現に置き換えて再指摘していないか
- [ ] バックログ記述をさらに精緻化できる余地があることと、現在の設計書が不合格であることを混同していないか
- [ ] 対応不要と確定した論点を除外一覧として管理し、追加指摘候補と照合したか

## 実際に発生した指摘ミス（要約）

- セキュリティ強化策（特定条件下での抑止策、経路を限定した情報取得等）を、本番インフラ構成確定前の現段階で対応必須と指摘したが、バックログ対応とユーザーが判断済みだった。
- 排他制御の対策拡大（検証範囲の拡大、定期的な状態更新等）を、低頻度リスクへの追加対策と現段階の必須対策のどちらとしてユーザーが判断済みか確認せずに指摘し、再鑑でも表現を変えて再指摘した。
- 対象の設計書が現行版・現行内容であることを確認せず、既に解消済みの論点や別階層の設計書の内容を指摘した。
