- 処理ステップ（`### N.`）の直下の処理内訳は、階層記号を先頭に付けたMarkdownリストとして、子要素をインデントしながら並べる。階層は(1)(2)…→①②③…→A.B.C.→(A)(B)(C)→a.→(a)の順（`design`スキルの「処理概要」節の階層2〜7に対応）で、兄弟要素の出現順に採番する。通常の逐次手順・条件分岐のいずれも、この階層記号付きのリスト項目（label）のみで表現し、分岐専用の記法は設けない。分岐条件を表す場合はlabelを「〜の場合」で始める。

### 3. 処理3

- (1) crudなどDB接続を伴う場合、処理をSQLと表の両方で記載する。

  - クエリの構造（JOIN・GROUP BY・ORDER BY・集計関数等を含む）はSQLで表現する。コメントは縦を揃えること。
  - SQLが最終的に扱う列は、複雑さによらず必ず以下の表で一覧化する。区分は、INSERT／UPDATEの登録・更新対象列は「登録内容」「更新内容」、WHERE句の絞り込み列は「検索条件」、SELECTの取得列は「取得内容」とする。
  - 集計関数の結果（`SUM(...)`等）や結合先テーブルの列も、SELECT句に並ぶ列としてそのまま1行ずつ記載する。JOIN条件・GROUP BYのグループ化軸そのものは列ではないためこの表には含めず、SQL側の記載のみとする。

  - 記載例）

  ```sql
  SELECT
    rv.id,                  -- 復習情報.id
    rv.item,                -- 復習情報.復習項目
    rv.description,         -- 復習情報.復習詳細
    rvm.review_time,        -- 復習管理情報.復習回
    rvm.review_date         -- 復習管理情報.復習日
  FROM
    review rv               -- 復習情報
  LEFT OUTER JOIN
    review_management rvm   -- 復習管理情報
  ON
    rv.id = rvm.review_id;  -- 復習情報.id = 復習管理情報.復習id
  ```

  | 区分 | 項目名 | 必須 | 設定値・設定元 | 備考 |
  |---|---|:---:|---|---|
  | 取得内容 | 復習情報ID | ○ | `review.id` | - |
  | 取得内容 | 復習項目 | ○ | `review.item` | - |
  | 取得内容 | 復習内容詳細 | ○ | `review.description` | - |
  | 取得内容 | 復習回 | - | `review_management.review_time` | LEFT OUTER JOINのため該当レコードがない場合は`NULL` |
  | 取得内容 | 復習予定日 | - | `review_management.review_date` | LEFT OUTER JOINのため該当レコードがない場合は`NULL` |
