# 要件定義工程の考え方

- 各種要件定義書は、AIエージェントがユーザーとの問答を通じて作成する。ただし仕様に関する決定（技術選定・設計判断等）はユーザーが行い、AIエージェントは選択肢の提示と、合意済み内容の文書化を担う。
- 形式はテンプレート（Markdown）通りに全て埋める必要がある。本工程が要求する成果物（レビュー・バージョン管理の対象）はMarkdown形式で統一する。
- テンプレートが埋まっていない場合、全ての項目が埋まるまで問答を行う。技術選定・設計判断についても選択肢を提示し、理由とともに確認を取ること。
- 各種要件定義書に仕様上の不足がある場合、不足分（何を選ぶか）は提案・確認を行いユーザーの合意を得る。合意済み内容の文書化、誤記・形式不備の修正はAIエージェントが直接行ってよい。
- 判断根拠書（判断根拠書.md）を要件定義工程の標準成果物とする。技術選定・設計・運用に関する判断について、検討した候補・採用理由・採用しなかった理由を記録し、後から追跡できるようにする。
- 要件定義書は複数ファイルにまたがるため、工程完了前に相互の整合性を確認する。特に技術スタック・アクセス制御・テスト方式など、複数箇所に記載がある項目は矛盾がないかチェックすること。
- 以降の工程の作業円滑化のため、プロジェクトに合わせたフォルダ構成も決めておく。レイヤー構成の定め（`design`スキルの「## レイヤー構成」節を参照）を踏まえ、責務ごとに適切に分離されたレイヤー構成とすること。具体例は`references/サンプル/フォルダ構成.md`を参照する。

---

## 作業手順
1. 概要の確認
2. 各種要件定義ファイル作成
    - テンプレートを参考に作成すること（`references/テンプレート/`）。
3. チェックリストを確認し、問題があればレビュー工程前なのでそのまま修正可能（`references/チェックリスト/要件定義.md`）。
4. 要件定義レビュー工程
    - `運用ルール/開発ルール/レビュー工程ルール.md`に従う。
