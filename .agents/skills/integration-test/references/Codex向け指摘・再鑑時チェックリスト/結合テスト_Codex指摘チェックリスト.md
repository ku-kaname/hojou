# 結合テスト Codex指摘・再鑑時チェックリスト

> **注記**：本チェックリストが前提とするCodex運用は、公開版v1時点では動作未検証の実験的機能です。Claude運用を正式サポート対象とし、Codexでの動作確認が取れ次第、正式サポートへ格上げします。

Codex（GPT-5）によるレビュー指摘・再鑑で実際に発生した指摘ミスを基にした、結合テスト工程向けのセルフチェック項目。技術スタックに依存しない、指摘・再鑑プロセス上の観点を扱う。人手（Codexによる自己再鑑を含む）でのレビュー時に使用する。技術スタック固有の事実確認ミスは`FastAPI/FastAPI_Codex指摘チェックリスト.md`・`React/React_Codex指摘チェックリスト.md`を参照する。

## MVP対象・対応時期の判定

- [ ] 実装側でバックログ対応・対応時期先送りと確定済みの論点（アクセス制御の検証範囲等）に対応する結合テストケースの追加を、現段階での対応必須として指摘していないか
- [ ] 技術的なリスクが存在することと、現在のMVP受入条件に含まれることを分けて判定したか

## 対象成果物・既存テストの事実確認

- [ ] 指摘対象のテスト仕様書・テストコードのパスが実際に存在することを確認したか
- [ ] 「未検証」と書く前に、`rg`等でプロジェクト全体を検索し、同じ契約・分岐・異常系を検証する既存テスト（単体テストを含む）がないことを確認したか
- [ ] ある階層（結合テスト）で未検証に見えても、他の階層（単体テスト）で責務に沿って直接検証済みではないか確認したか
- [ ] 「この場所では確認できない」ことを「プロジェクト全体で未実装・未検証」と誤って扱っていないか

## 再鑑時の確認

- [ ] 一度MVP対象外・バックログと確定した事項を、再鑑で別表現に置き換えて再指摘していないか
- [ ] 対応不要と確定した論点を除外一覧として管理し、追加指摘候補と照合したか

## 実際に発生した指摘ミス（要約）

AI生成処理共通の結合テスト仕様書で、実DB並行テストの追加を現段階での対応必須として指摘したが、その前提となる実装側の対応拡大がバックログ登録済みであり、実装完了後に追加するとユーザーが判断済みだった。
