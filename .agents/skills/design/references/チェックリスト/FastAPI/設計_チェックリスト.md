# 設計 チェックリスト（FastAPI）

## 引数・バリデーション設計

- [ ] 引数定義表にフレームワークが自動返却する HTTP 422（バリデーションエラー）を記載しているか
- [ ] multipart/form-dataでファイルを受け取るエンドポイントを設計する際、ファイルパラメータがPydanticモデルの項目なのか、エンドポイントの独立したFile/Formパラメータなのかを実装方式として明記したか
- [ ] 同一機能について複数の設計書（スキーマ定義書・処理記述書）を作成する場合、一方の設計書で誤った実装方式の前提を置いていないか、もう一方の設計書作成時に突き合わせたか

## 認証・認可設計

- [ ] FastAPI の依存性注入（`Depends`）で注入される認証関数（例：`get_user`）がどのフィルタ条件でユーザーを取得しているかを把握しているか
  - 例：`get_user` が `delete_flag==False` でフィルタするなら、削除済みチェックは認証層でブロック済みであり個別エンドポイントへの実装は不要
- [ ] 認証系エンドポイント（ログイン・パスワードリセット等）の設計時、総当たり攻撃対策（レート制限）を要件として洗い出したか
- [ ] 認証系エンドポイントで、応答文言の統一（ユーザー列挙対策）だけでなく、処理経路の分岐による応答時間差（タイミングサイドチャネル）も検証したか
- [ ] ミドルウェア型のレート制限を導入する際、実際のデプロイ構成（リバースプロキシ有無・プロセス数）を前提にIP取得方法とカウンター共有方式が機能するか確認し、既知の制約は設計書に明記したか
