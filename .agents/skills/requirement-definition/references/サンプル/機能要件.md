## アクセス制御

### 認証要否

| 機能 | 認証要否 |
|---|---|
| ユーザー登録 | 不要 |
| ログイン | 不要 |
| ユーザー情報取得 | 要（JWTトークン） |
| ユーザー更新 | 要（JWTトークン） |
| ユーザー削除 | 要（JWTトークン） |
| 全ユーザー情報取得 | 要（JWTトークン・管理者のみ） |
| ユーザー更新（管理者） | 要（JWTトークン・管理者のみ） |
| ユーザー削除（管理者） | 要（JWTトークン・管理者のみ） |
| 復習情報登録 | 要（JWTトークン） |
| 復習情報取得 | 要（JWTトークン） |
| 復習情報更新 | 要（JWTトークン） |
| 復習情報削除 | 要（JWTトークン） |

### 認可ルール
- 一般ユーザーは自分のデータのみ操作可能（リクエストの user_id と JWTトークンの user_id が一致する場合のみ許可）
- 管理者（admin_flag=True）は全ユーザーのデータを操作可能

### 管理者アカウントの作成
- 管理者ユーザーは環境変数（ADMIN_SECRET_KEY_NAME・ADMIN_SECRET_KEY_PASSWORD）で管理するシード管理者のみ作成可能
- 一般ユーザーのユーザー登録では管理者フラグをTrueにすることはできない

## 業務ルール

### 論理削除ユーザーのログイン
- 削除フラグがTrueのユーザーはログイン不可
- 削除済みユーザーでログインを試みた場合はHTTP 401を返す

### ユーザー論理削除時のデータ扱い
- ユーザーを論理削除した場合、紐づく復習情報（REVIEWテーブル・REVIEW_MANAGEMENTテーブル）はデータを保持する
- 削除済みユーザーはログイン不可のため、保持されたデータには事実上アクセスできない

### ユーザー名重複登録時の挙動
- 既に登録済みのユーザー名でユーザー登録を試みた場合、HTTP 400（Bad Request）を返す
- 論理削除済み（削除フラグ=True）のユーザーのユーザー名も重複チェックの対象に含め、再利用不可とする

### パスワードの入力要件
- ユーザー登録（F01）・ユーザー更新（F04）でパスワードを受け取る際、8文字以上をサーバー側で必須検証する
- 検証エラー時はHTTP 400（Bad Request）を返す

### 学習日未入力時の挙動
- 復習情報登録時に学習日が未入力の場合、登録日時を学習日として自動設定する

## 扱うデータ
- 主要データ：ユーザー、復習情報、復習スケジュール（復習回ごとの対応済みフラグを含む）
- 保持期間：定めなし（ユーザーの論理削除後もデータを保持する。詳細は「業務ルール」を参照）
- パスワードはハッシュ化して保存する（詳細は非機能要件.mdの「セキュリティ」を参照）
