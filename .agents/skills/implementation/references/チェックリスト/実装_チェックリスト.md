# 実装 チェックリスト

各項目には`[IMPL-CHK-01]`〜`[IMPL-CHK-18]`の固定IDを付与している。AIによる実装コード生成の自己レビューでは、このIDにより後述の○判定範囲分類で「全体」「ファイル単位」を判定し、生成した実装コード全ファイルを俯瞰しないと判定できない項目（全体）とファイル1件で完結する項目（ファイル単位）を二段構成でチェックする。人手によるレビュー（レビュー指摘表運用時の目視確認等）で用いる場合はIDを意識する必要はなく、そのままチェックリストとして使用してよい。

## コードと設計書の照合

- [ ] [IMPL-CHK-01] メソッド名・関数名が設計書と一致しているか
- [ ] [IMPL-CHK-02] データモデルのフィールド名とコード内の変数名が一致しているか（誤記に注意）
- [ ] [IMPL-CHK-03] レスポンスの全フィールドがスキーマ定義と1対1でマッピングされているか

## フレームワーク・ライブラリの利用

- [ ] [IMPL-CHK-04] 使用するフレームワークが推奨するモジュール分割・ルーティングの方法に従っているか（非推奨パターンで実装していないか）
- [ ] [IMPL-CHK-05] ORMやデータアクセス層でのクエリ構築が、フレームワークの推奨パターンに沿っているか
- [ ] [IMPL-CHK-06] スキーマ・モデルの継承や合成によって、意図しないフィールドが引き継がれていないか
- [ ] [IMPL-CHK-07] 非推奨のモジュール・APIを使っていないか（使用ライブラリのバージョンに応じた最新推奨方法を確認する）

## 例外処理

- [ ] [IMPL-CHK-08] 例外キャッチの範囲が適切か（ビジネスロジックの例外処理が広範な例外ハンドラに意図せず捕捉されていないか）
- [ ] [IMPL-CHK-09] 認証フロー全体を把握した上で例外処理を実装しているか（認証層でブロック済みの条件を二重に実装しない）

## 型の整合性

- [ ] [IMPL-CHK-10] バリデーション条件が引数の型と整合しているか（到達不能な比較・条件を記述していないか）
- [ ] [IMPL-CHK-11] スキーマのバリデーション上限値が要件定義の制約と一致しているか

## アーキテクチャ原則

- [ ] [IMPL-CHK-14] レイヤー間の呼び出しが一方向（エンドポイント層→オーケストレーション層→データアクセス層）になっているか、上位レイヤーが下位レイヤーを直接呼び出していないか（`design`スキルの「## レイヤー構成」で例外とするヘルスチェックを除く）
- [ ] [IMPL-CHK-15] ファイル間で命名・インポートパスの一貫性が保たれているか（同一クラス・関数が複数ファイルで重複定義されていないか）

## 変更後の整理

- [ ] [IMPL-CHK-12] 設計変更・修正後に不要になったコード・クラスを削除したか
- [ ] [IMPL-CHK-13] 同じ問題が他のファイル・他の機能にも存在しないか横展開確認したか
  - 相互依存するモジュール（ルーティング・データアクセス・スキーマ等）は、1箇所の変更が他に影響しないか確認する

## 機械的検証の信頼性確認

- [ ] [IMPL-CHK-16] 機械的検証（スクリプトによる網羅チェック）を導入する際、検証対象範囲（走査するディレクトリ・ファイルパターン）が対象全体を再帰的に網羅しているか確認したか
  - 「スクリプトで機械的に検証した」という回答自体を鵜呑みにせず、走査範囲・抽出条件を実際に確認する
  - 正規表現による文字列抽出は区切り文字の想定漏れによる誤検出・見落としの双方が起こりうるため、実在ファイル一覧との突き合わせに加え誤検出候補も個別に確認する

## 排他制御・同時実行制御

- [ ] [IMPL-CHK-17] 排他制御・同時実行制御を実装する際、「同時到達」「処理途中の失敗（クレーム成功後の後続処理失敗でロックが解放されない等）」「所有権の失効と復帰」の3パターンを正常系とは別に実装したか
  - リース失効による回収機構を導入する場合、回収後の所有権が新要求へ正しく移ることを保証する所有者トークンの仕組みを含めたか（共有キーのみでの排他判定にしていないか）
- [ ] [IMPL-CHK-18] 複数のエンドポイントが同一の定型構造（ステータス確認→外部API呼び出し→状態更新等）を持つ場合、1つのエンドポイントで見つかった排他制御・異常系処理の欠陥を、同一構造を持つ他の全エンドポイントへ横展開して確認したか

## ○判定範囲分類

各チェック項目が、生成済みファイルのうち何件を俯瞰すれば判定可能かを示す分類。新規追加するチェック項目は、この表に判定範囲分類を追加登録することで自動的に絞り込み対象へ反映される。

| ID | 判定範囲分類 | 説明 |
|---|---|---|
| IMPL-CHK-01 | ファイル単位 | 1ファイル内の関数・メソッド定義と、対応する処理記述書1件を突き合わせれば判定できる |
| IMPL-CHK-02 | ファイル単位 | 1ファイル内の変数名とテーブル定義書の対応関係のみで判定できる |
| IMPL-CHK-03 | ファイル単位 | 1ファイル（レスポンスを組み立てる箇所）とスキーマ定義書の対応関係のみで判定できる |
| IMPL-CHK-04 | ファイル単位 | 1ファイル内のモジュール分割・ルーティング方法のみで判定できる |
| IMPL-CHK-05 | ファイル単位 | 1ファイル（データアクセス層）内のクエリ構築のみで判定できる |
| IMPL-CHK-06 | ファイル単位 | 1ファイル内のスキーマ・モデル定義のみで判定できる |
| IMPL-CHK-07 | ファイル単位 | 1ファイル内で使用しているモジュール・APIのみで判定できる |
| IMPL-CHK-08 | ファイル単位 | 1ファイル内の例外キャッチ範囲のみで判定できる |
| IMPL-CHK-09 | ファイル単位 | 1ファイル内の認証依存性注入の使用箇所のみで判定できる |
| IMPL-CHK-10 | ファイル単位 | 1ファイル内のバリデーション条件と引数の型のみで判定できる |

| IMPL-CHK-12 | 全体 | 不要コードの削除漏れは、生成済み全ファイルを俯瞰しないと判定できない |
