# 要件定義 チェックリスト

## 機能一覧

### 機能一覧
- [ ] 一般ユーザーが行える操作を全て列挙しているか
- [ ] 管理者のみが行える操作を明示しているか
- [ ] 管理者ユーザー自体をどのように作成・管理するか、機能一覧または機能要件（アクセス制御）に記載しているか

## 機能要件

### アクセス制御
- [ ] どの機能・リソースに認証が必要か・不要かを一覧で明示しているか
- [ ] ユーザーは自分のデータのみ操作可能か、他のユーザーのデータも操作可能かを明示しているか
- [ ] 管理者の認可範囲（全ユーザーデータへのアクセス可否）を明示しているか

### 業務ルール・エッジケース
- [ ] 論理削除を採用する場合、削除済みデータへの各操作の挙動を定義しているか
  - 削除済みユーザーがログインを試みた場合の挙動（例：認証エラーとして弾く）
  - 削除済みユーザーに紐づくデータの扱い（保持 or 削除）
- [ ] 重複登録時の挙動を定義しているか（例：同一ユーザー名登録時のエラー）
- [ ] 自動生成・自動計算される値のロジックを定義しているか

## データ要件

### データモデル定義
- [ ] 各フィールドの型を定義しているか
- [ ] 各フィールドの文字数・桁数制限を定義しているか
- [ ] 各フィールドの必須・任意を定義しているか
- [ ] デフォルト値が必要なフィールドにデフォルト値を定義しているか
- [ ] 採番ルールを定義しているか（例：IDをユーザーごとに採番するか、グローバルで採番するか）
- [ ] 関連データ削除時の連動動作を定義しているか（連鎖削除 or データ保持）

## 新機能追加時の横展開確認

- [ ] 新機能追加が既存の判断根拠書の判断事項と矛盾しないか確認したか。矛盾する場合は新規判断として追記し、旧判断側にも改訂の経緯を追記したか
- [ ] 新機能追加時、アクセス制御の認証要否表に新機能の行を追加したか
- [ ] 新機能追加時、成果物の生成順序を定めた業務ルールに新機能を追加したか
- [ ] 新機能追加時、既存のダウンロード対象・エクスポート範囲等の業務ルールに新機能の成果物を追加する必要がないか確認したか
- [ ] 新機能特有の構成方針（分割理由・トリガー条件・適用範囲の考え方等）を明文化する業務ルールを新設したか

## 基礎資料の鮮度確認

- [ ] 新規モジュール・新機能を追加した際、それを反映すべき要件定義工程の基礎資料（機能一覧等）に追加内容を反映したか
- [ ] 開発プロセス方針を確定・変更した際、機能一覧の該当機能の説明文へ反映したか

## 確認の問いかけ

要件定義作成時に以下の問いを意識する。

- 「このデータが存在しない・無効な場合はどうなるか？」
- 「誰がこの操作を実行できるか？できない場合はどうなるか？」
- 「削除・無効化されたデータに対して各操作はどう振る舞うか？」
- 「この新機能は、既存のどの章・どの業務ルール・どの判断事項に影響するか？」
- 「影響する箇所をすべて洗い出さずに、思いついた箇所だけ直していないか？」
