# 結合テストの考え方

- 確認観点としては、以下を考慮した結果になるかどうかを確認する。
    - 前提条件
    - 入力
    - 出力
- 設計書の条件分岐を網羅し、想定通りの結果が得られるかを確認する。
    - 正常系・異常系のどちらも対象とする。
    - 設計書に記載がない場合でも、テストすべきものがあればテストを行う。

---

## 作業手順
1. 設計書の確認
2. 結合テスト仕様書作成
    - 結合テストの考え方に基づきテスト仕様書を作成する。
    - `design`スキルのサンプル処理記述書（復習項目更新）を参考に作成した例は`references/サンプル/復習項目更新_結合テスト仕様書.md`に格納している。
3. チェックリストを確認し、問題があればレビュー工程前なのでそのまま修正可能。
4. 結合テスト仕様書レビュー工程
    - `運用ルール/開発ルール/レビュー工程ルール.md`に従う。
5. テストコード作成
    - ユーザーはシステム作成の知識がないことを前提に、テストコードには分かりやすくコメントを付与すること。
    - テストコードは、「## テストコードの形式」に従って記載すること。
6. 結合テストコードレビュー工程
    - `運用ルール/開発ルール/レビュー工程ルール.md`に従う。
7. テスト実行
    - エラーがあれば指摘表を記載して修正する。

---

## テストコードの形式
- ファイルの冒頭（import文がある場合はその後）に、ヘッダーとして以下を記載する。
    - 機能論理名
    - テスト対象ファイル
    - テスト対象クラス（クラスがない場合は`-`）
    - テスト対象メソッド
    - テスト仕様書（格納パス）
- テスト関数ごとに、関数の直前に、結合テスト仕様書の項番とテスト項目を記載する。
- テスト関数名は、`test_<テスト対象メソッド名>_<項番（3桁）>_<内容>`とする。
- Python以外の言語も、その言語のコメント記法で、同じ項目を記載する。

以下はPython（pytest）の例。
```python
# ==================================================
# 復習項目更新
# テスト対象ファイル：main.py
# テスト対象クラス：-
# テスト対象メソッド：update_review_endpoint
# テスト仕様書：テスト仕様書/結合テスト仕様書/サーバー処理/復習項目操作/復習項目更新_結合テスト仕様書.md
# ==================================================

# ========== 結合テストNo.1 ==========
# 復習項目名を更新した場合、HTTP 200 と更新後の review_item が返却されること
def test_update_review_endpoint_001_update_review_item(client, make_token):
    ...
```
