# Issueルール

## タイトル形式

Issueタイトルは、対応するバックログのバックログ名とする（例：`設計（ユーザー操作）`）。

- 完了バックログの`bk/`への格納のIssue（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「タスクの完了・追加」参照）は、バックログに当たらないため、タイトルを`バックログ整理`とする。

---

## 概要テンプレート

```markdown
## 作業スコープ
- 対象ファイル・機能を記載（例：設計書/CRUD/ユーザー操作 配下の指摘対応）

## 完了条件
- [ ] 完了したらクローズする条件を1行に1つ記載（例：指摘No.1 ユーザー作成 対応完了）

## 関連（任意）
- 指摘No.番号 / 関連Issue番号など
```

---

## PRのタイトルと概要

PRタイトルは、Issueタイトルをそのまま使用する（IssueとPRは1対1で対応させる）。PRの概要には、対応するIssueを、PRのマージ先（[ブランチルール](ブランチルール.md)参照）に応じて以下の形式で記載する。

| マージ先 | 概要の記載 | Issueのクローズ |
|---|---|---|
| `main` | `Closes #○○` | マージ時に自動でクローズされる |
| `dev` | `Related: #○○` | PRのマージを確認してから、手動でクローズする（例：`gh issue close ○○`） |

- GitHubは、デフォルトブランチ（`main`）へのマージでのみ、`Closes #○○`のIssueを自動でクローズする。`dev`へのマージではクローズされないため、`dev`をマージ先とするPRには`Closes`を記載しない。

PRマージ・Issueクローズを確認したら、対応したブランチをローカル・リモート双方から削除する（マージ済みブランチへの追加コミットは行わない。再度対応が必要になった場合は新たなIssue・ブランチを作成する）。

---

## PRに含める変更

PRには、対応するIssue（バックログ）の「作業スコープ」「完了条件」に属する変更のみを含める。PR（＝1バックログ）の規模は、[作業管理ルール](../作業管理ルール/作業管理ルール.md)「1PRの規模の目安」に収める。

### 含めてよい付随変更

以下は、作業スコープに明記されていなくても、同じPRに含めてよい。

- 当該バックログの作業管理・引継ぎ資料の更新（状態の`完了`への更新を含む。[作業管理ルール](../作業管理ルール/作業管理ルール.md)「タスクの完了・追加」参照）
- 本PRの変更に伴って必要になった追従修正（ファイル名の変更に伴う参照の修正等）
- 範囲外の依頼を受けた際の`【一覧取込待】_<バックログ名>.md`の作成（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「対応中バックログの範囲を超える依頼への対応」参照）
- バックログの分割に伴う`バックログ一覧.md`の更新（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「バックログの分割単位」「作業中のバックログ分割」参照）
- 当該バックログのレビュー工程で、影響がある他の機能群の成果物へ指摘した箇所の修正（[レビュー工程ルール](../開発ルール/レビュー工程ルール.md)「手順」1参照）
- 作業中に見つけた軽微な誤りの修正のうち、以下をすべて満たすもの
    - 本PRで既に変更しているファイル内の箇所である
    - 誤字・旧名称・リンク切れ・古くなった説明等の表記の修正であり、内容・ルールの意味を変えない
    - 修正内容をPRの概要に記載する

### 含めない変更

- 他のバックログに属する変更
- 上記の付随変更に当たらない範囲外の修正（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「対応中バックログの範囲を超える依頼への対応」に従う）
- 完了バックログの`bk/`への格納（本体PRのマージ確認後、専用のIssue・PRで行う。[作業管理ルール](../作業管理ルール/作業管理ルール.md)「タスクの完了・追加」参照）

### 機械的な一括変更

工程・機能群をまたぐ多数のファイルへ同じ種類の変更を機械的に行うもの（プロジェクト完了時の成果物のv1.0.0への更新に伴うファイル名の変更、テンプレート改訂に伴う一括修正等）は、内容の変更と同じPRに含めず、単独のバックログ・PRで行う。この変更に伴う追従修正（ファイル名の変更に伴う参照の修正等）は、同じPRに含めてよい。
