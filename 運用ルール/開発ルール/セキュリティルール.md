# ハッシュ化アルゴリズム
- 新規開発の場合は現時点での世界標準（Argon2id）を推奨すること。

# 秘密情報管理
- APIキー・パスワード・トークン等の秘密情報はソースコード・設定ファイルへ直接記載せず、環境変数または秘密情報管理サービスから取得すること。
- `.env`等の秘密情報を含むファイルはリポジトリへコミットしないこと（`.gitignore`へ登録）。

# 認証・認可
- 認証方式（JWT等のトークン方式、APIキー、OAuth等）はプロジェクトの要件に応じて選定し、選定理由を判断根拠書に記録すること。
- トークン・APIキー等の認証情報には有効期限・失効の仕組みを設けること。
- エンドポイントごとに、認証要否・アクセス可能なロール／ユーザーを設計書に明記すること。

# 入力値検証
- 外部から受け取る全ての入力値（リクエストボディ・クエリパラメータ・パス変数等）に対し、型・必須・長さ・形式の検証を行うこと。
- クライアント側の検証だけでなく、サーバー側でも必ず検証すること。

# インジェクション対策
- SQL・OSコマンド等を組み立てる際、文字列連結ではなくプレースホルダ・パラメータ化クエリを使用すること。
- ORMを使用する場合も、生SQLを組み立てる箇所がないか確認すること。

# 依存関係管理
- 使用するライブラリ・パッケージに既知の脆弱性がないか定期的に確認すること。
- 長期運用するプロジェクトでは、依存パッケージの更新方針を非機能要件（「運用・保守」）に記載すること。

# ログの機密情報
- パスワード・トークン・個人情報等の機密情報をログへ出力しないこと。

# 通信
- 外部との通信は暗号化（HTTPS/TLS）を必須とすること。

# ファイル操作
- ユーザーが指定したパス・ファイル名をそのままファイルシステム操作に使用せず、パストラバーサル等を防止すること。
- アップロードされたファイルは想定する種類・サイズを検証すること。

# 個人情報
- 個人情報を扱う場合、保存・利用目的・保持期間をプロジェクトの機能要件（「扱うデータ」）に明記すること。

# セキュリティテスト
- 認証・認可、入力値検証等のセキュリティに関わる処理は、単体テスト・結合テストの対象に含めること。
