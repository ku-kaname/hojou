# 設計 チェックリスト（Claude API）

## 出力スキーマ・プロンプトの制約確認

- [ ] 出力スキーマ（JSON Schema）のフィールド数・ネスト階層が多い機能は、grammar too large（スキーマ複雑度上限）のリスクを見積もり、最初から段階分割を前提とした設計にしたか
- [ ] プロンプトキャッシュ（cache_prefix）を導入するテンプレートで、プレースホルダーの配置順序が「固定部分→可変部分」になっているか確認したか

## バッチ処理・再開処理の堅牢性確認

- [ ] 外部API（Claude API等）へバッチ依頼を投げる処理で、応答件数・キーの完全一致を検証するロジックを設計に含めたか
- [ ] 中断・再開の仕組み（resume_results等）を設計する際、保存された再開データが常に正しいと決め付けず、再開時の整合性検証を含めたか
