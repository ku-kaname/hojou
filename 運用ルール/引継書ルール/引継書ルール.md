# 引継書ルール

引継ぎ資料は目的の異なる2種類（機能別・タスク毎）を作成する。3種類目以上のファイルは作らない。

| 種類 | 目的 | 格納場所 | 対象範囲 |
|---|---|---|---|
| 機能別 | 機能に対してどのような意図でどのように対応したかを記録・蓄積し、保守性を向上させる | `引継ぎ資料/機能別/<機能ID>_機能名/引継書.md` | 全工程共通（初期開発・プロジェクト改修とも必須） |
| タスク毎 | 作業の進行状況を記録し、進行の道標とする | `引継ぎ資料/タスク毎/<短い名称>_引継書.md` | 全工程共通（[作業管理ルール](../作業管理ルール/作業管理ルール.md)のバックログ／タスク単位。初期開発は工程ごとに1バックログを登録し、各工程の着手時に分割する） |

- プロジェクト開始時、要件定義工程に入る前にこのバックログ・タスク一覧を登録する（詳細は[作業管理ルール](../作業管理ルール/作業管理ルール.md)「初期開発での運用」を参照）。
- 機能別引継ぎ資料は工程ごとには作成せず、プロジェクト完了時に一括で作成する（詳細は「全体の運用フロー」を参照）。
- 機能ID・機能名は、要件定義工程の成果物（機能一覧など、プロジェクトごとの呼称による）で確定したF番号・S番号をそのまま使う。該当する成果物がない場合は、機能単位でIDを新規に振ってよい。

---

## フォルダ構成

```
引継ぎ資料/
  機能別/
    <機能ID>_機能名/
      引継書.md                     … 現在の状態のみを表す
      bk/
        引継書_v1.md                … 旧版（版数は古い順にv1, v2, ...）
        引継書_v2.md
    全体方針/                       … 全体方針に関わるものを記載する
      引継書.md
      bk/
        引継書_v1.md
  タスク毎/
    <バックログ名称>_<タスク名>_引継書.md            … `bk/`へ移す前のタスク（進行中・完了とも。初期開発はバックログ名称に工程名を用いる（分割時は工程名＋機能群名）、例：設計（共通）_テーブル定義書作成_引継書.md）
    bk/
      <バックログ名称>_<タスク名>_引継書_yyyymmdd.md … `bk/`へ移したタスク（バックログの`bk/`格納時に移す。yyyymmddはタスクの完了日）
```

---

## 機能別の運用

- 常に「現在の状態」のみを表すファイルとする。更新するたびに（タイミングは「全体の運用フロー」を参照）、旧内容を`引継書_v◯.md`にリネームして`bk/`へ退避してから、新しい`引継書.md`を作成し直す。
- 過去の経緯のうち、現状を理解するうえで不要になったものは書き直しのタイミングで削ってよい。詳細な旧内容は`bk/`の旧版を参照すればよいため。
- 複数機能にまたがる対応（共通メソッドの追加・修正・削除、画面全体のスタイル統一など）は、共通フォルダを新設せず、関係する機能フォルダすべてに同じ内容を重複して記載する。
- どの機能にも紐づかない内容（工程全体のサマリ、プロジェクト全体のルール・方針変更など）は「全体方針」フォルダに記載する。
- 機能別引継ぎ資料は、開発完了後の改修フェーズで参照される長期的な申し送りであり、タスク毎引継ぎ資料の要約として作成・書き直すため、内容の欠落が後続作業から気づきにくい。そのため、作成・更新後にユーザーの確認を受ける（利用側プロジェクトのAGENTS.md等で省略してよい）。

## タスク毎の運用

[作業管理ルール](../作業管理ルール/作業管理ルール.md)のバックログ／タスク構造（「誰に／何を／なぜ」のバックログと、その実現手段であるタスクを分けて管理する構造）を採用する工程で作成する。

- タスク一覧.mdのタスク名に対応させるが、優先度変更で並び順が入れ替わりうるため、ファイル名には順序を示す番号を付けず短い名称のみを使う。
- 対応するタスク詳細ファイルと同じ単位・同じ名称に`_引継書`を付けたファイル名（`<バックログ名称>_<タスク名>_引継書`）を使う（例：「生成コストの見直し_プロンプトキャッシュの実装_引継書」）。
- 作業のたびに追記し続ける（機能別と異なり書き直さない）。
- タスクが完了しても、引継書はその場に残す。バックログを`bk/`へ格納する際（[作業管理ルール](../作業管理ルール/作業管理ルール.md)「タスクの完了・追加」の手順に従う）、当該バックログの各タスクの引継書を、削除せず`<バックログ名称>_<タスク名>_引継書_yyyymmdd（タスクの完了日）.md`にリネームして`bk/`へ移動する（タスク一覧.mdの行の扱いも同ルールに従い、削除せず状態を`完了`にする）。

## 全体の運用フロー

### 初期開発（要件定義〜プロジェクト完了工程）

- タスク毎引継ぎ資料は、工程ごとに、レビュー工程の区切りを待たず作業のたびに追記し続ける。
- 機能別引継ぎ資料は、個々のレビュー工程（[レビュー工程ルール](../開発ルール/レビュー工程ルール.md)の手順2・6）では作成・更新せず、**プロジェクト完了時に、各工程のタスク毎引継ぎ資料の内容をもとに機能ごとに一括で作成する**（[プロジェクト完了の考え方](../../.agents/skills/project-completion/SKILL.md)に従う）。
    - 理由：機能別の目的（保守性向上のための申し送り）は、開発完了後のプロジェクト改修フェーズで主に活きる。開発中の継続的な進捗ログはタスク毎資料が担うため、機能別を工程ごとに書き直す必要はなく、プロジェクト完了時に一貫した状態としてまとめて作成すればよい。

### プロジェクト改修

- タスク毎引継ぎ資料は、レビュー工程の区切りとは独立した以下のタイミングで運用する。
    1. 作業開始前に、タスク一覧.mdを作成・更新する（[作業管理ルール](../作業管理ルール/作業管理ルール.md)に従う）。
    2. 以後、個々のレビュー工程の完了を待たず、作業のたびに追記し続ける。
- 機能別引継ぎ資料は、タスク進行中の個々のレビュー工程（手順2・6）では作成・更新せず、**タスクが完了したタイミングでまとめて作成・書き直す**。1つのタスクが複数機能に影響する場合、影響を受けた機能それぞれの`引継書.md`に、当該タスクのタスク毎引継ぎ資料の内容をもとに反映する。
    - 理由：プロジェクト改修の1タスクは複数のレビュー工程を横断することが多く、個々のレビュー工程完了ごとに機能別を書き直すと、タスクとして未完成な断片的状態が機能別側に何度も記録されてしまう。継続的な進捗ログはタスク毎資料が担うため、機能別側はタスク完了時点の一貫した状態のみを反映すればよい。

## 作業時間の計測

タスクにかかった実働時間を可視化するため、以下の運用を行う（初期開発・プロジェクト改修とも共通）。

- タスク毎の進捗ログへの追記のたびに、タスク毎引継ぎ資料の「## 作業ログ」セクションへ、その作業セッションの開始・終了時刻を1行追記する。時刻は記憶や推測で埋めてはならず、記載する都度、実際の時計を確認するコマンド（例：`date`、PowerShellなら`Get-Date`）を実行し、その出力をそのまま転記すること。

    ```
    ## 作業ログ
    - 開始: 2026-09-11 10:03:15 / 終了: 2026-09-11 11:45:02
    - 開始: 2026-09-11 14:00:40 / 終了: -
    ```

    - 日時は`yyyy-mm-dd hh:mm:ss`とし、開始・終了とも年月日から省略せずに記載する。
    - 終了が未記入（進行中）の行は`終了: -`と記載し、次回の区切りで実際の終了時刻に書き換える。
    - 1タスクが複数日・複数セッションにまたがる場合は行が積み上がり、そのままタスクにかかった実働時間の内訳になる。
    - 別のタスクの作業ログと時間帯を重ねない（作業コストの集計で二重に計上されるため）。

- Claude Codeで作業ログの自動記録（hojouのREADME「任意設定：作業ログの自動記録」）を導入している場合（`.claude/settings.json`に`worklog-hook.ps1`のhookが登録されている場合）は、AIは作業ログを記載せず、`worklog-record.ps1`が会話記録から求めた作業区間を書き込む。
    - hookは、セッションの開始時・要約の後等に、そのセッションのセッションIDを会話へ出力する。
    - `worklog-record.ps1`は、Claude Codeの会話記録（transcript）の時刻から、ユーザーの発言から応答の終了までのAIの作業区間を秒単位で求める（ユーザーの返事待ち・選択式の質問（AskUserQuestion）の回答待ちは含めない）。
    - AIは、タスク毎引継ぎ資料をコミットする直前に、次のコマンドを実行し、書き込まれたタスク毎引継ぎ資料も含めてコミットする。そのセッションで前回の書き込み以降の作業区間が、指定したタスク毎引継ぎ資料の「## 作業ログ」へ書き込まれる。

        ```
        powershell -NoProfile -ExecutionPolicy Bypass -File hojou/scripts/worklog-record.ps1 -SessionId <セッションID> -Path "<タスク毎引継ぎ資料のパス>"
        ```

    - 重なる・接する（終了と次の開始が同じ時刻の）作業区間は1行にまとめる。
    - AIは、作業ログの行を追記・編集しない。
    - hookを導入していない場合（Codex等、Claude Code以外のAIエージェントを含む）は、上記のとおりAIが記載する。
