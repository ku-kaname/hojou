# プロジェクト完了の考え方

## 作業手順

- 全ての工程が完了したら、README.mdを作成し、ユーザーがこのシステムを使用するための情報を記載する。
- 各工程のタスク毎引継ぎ資料の内容をもとに、機能ごとに機能別引継ぎ資料を一括で作成する（`運用ルール/引継書ルール/引継書ルール.md`に従う）。
- 初回開発で、v1.0.0未到達の成果物がある場合は、`運用ルール/開発ルール/バージョン管理ルール.md`に従い、それらをv1.0.0にする。これは成果物のバージョンの更新であり、システムのバージョン（gitタグ`v1.0.0`）の付与は、v1.0.0の公開時に行う（`運用ルール/GitHubルール/ブランチルール.md`参照）。
- README.mdの作成、機能別引継ぎ資料の一括作成、成果物のv1.0.0への更新（初回開発時のみ）、完了チェックリストの実施がすべて完了した時点をプロジェクト完了とする。
- プロジェクト完了後、v1.0.0を公開するかをユーザーに確認する（hojouのgit運用ルールを適用している場合）。公開する場合は、本工程のPRが`main`へマージされた後、`運用ルール/GitHubルール/ブランチルール.md`「新規開発完了時（v1.0.0になったタイミング）」に従い、タグ`v1.0.0`の付与と`dev`の作成を行う。
